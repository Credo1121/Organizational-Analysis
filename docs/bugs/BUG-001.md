# BUG-001: GitHub Pages zeigt README statt Bericht

Status: Lokal behoben und verifiziert, Pages-Liveprüfung blockiert · 06.11.2026 · Bezug REQ-07 / REL-001.

## Befund und Reproduktion

Nutzer-Screenshot zeigt eine durch GitHub Pages gerenderte README (Projektbeschreibung und Installationsanleitung). Vor Fix enthält Commit 317da51 nur docs/index.html, keine index.html im Repository-Hauptordner. Wenn Pages den Hauptordner veröffentlicht, fehlt dort der HTML-Einstieg; GitHub kann stattdessen die README rendern. Tatsächliche Pages-Einstellungen sind wegen des blockierten API-Zugriffs nicht direkt gelesen; die Root-Quellkonfiguration ist deshalb eine durch Screenshot und Dateibefund gestützte Diagnose.

Regression vor Fix: tests/pages-entry.test.mjs prüft beide Quellordner am Repository-Basispfad /Organizational-Analysis/. Root-Test schlägt wegen fehlender index.html fehl, docs-Test funktioniert. Keine Simulation einer vermeintlich echten GitHub-Vorher-Aufnahme; Nutzer-Screenshot ist der Live-Vorher-Nachweis.

## Erwartetes Verhalten und Fix

- AC-01: Veröffentlichung von main / zeigt die Berichtsdemo mit Radar statt README.
- AC-02: Veröffentlichung von main /docs funktioniert weiterhin mit demselben Inhalt.
- AC-03: Quellen-Drill-down, Priorisierung und Dateidownload funktionieren auch unter dem Repository-Basispfad.
- AC-04: Keine neuen Backend-/KI-Funktionen oder echten Daten durch den Fix veröffentlichen.

scripts/build-pages.ts schreibt nun denselben ausschließlich synthetischen Bericht und .nojekyll an beide möglichen Quellorte. Keine Änderung der GitHub-Einstellungen nötig, keine Redirect- oder JavaScript-Abhängigkeit für den Einstieg. Der Root-Einstieg ist ein statisches Pages-Artefakt; die Next.js-App bleibt unverändert.

Fixversuche dieser Ursache: 1. Vor Fix: Root FAIL, docs PASS. Nach Fix: beide Browserläufe PASS. [Prüfungen, Screenshots und Auslieferung](../changes/CHG-004.md).
