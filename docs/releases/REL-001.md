# REL-001: GitHub-Übergabe und optionale Pages-Berichtsdemo

Datum: 06.11.2026. Autorisierung: Nutzer fordert ausdrücklich Push nach GitHub; er möchte die Repository-Sichtbarkeit selbst auf Public ändern und über GitHub hosten. Keine Autorisierung für die Auswahl eines anderen Hostinganbieters oder Änderung der lokalen App zu einer öffentlichen Backend-App.

## Umfang

Vollständiger lokaler PoC aus CHG-002 einschließlich synthetischer Tests und Dokumentation. Ergänzend eine optionale Pages-Berichtsdemo unter docs/index.html. Sie wird ausschließlich aus src/domain/demo.ts generiert, greift niemals auf src/server/store oder lokale Daten zu und bezeichnet sich als fiktiven Beispielbericht. Node-/SQLite-Backend bleibt unverändert lokal. Keine Gateway-Zugangsdaten vorhanden.

GitHub Pages kann HTML/CSS/JavaScript ausliefern, aber keinen Node.js-/Next.js-Server mit SQLite und App-Login betreiben. Die statische Demo ist daher ausdrücklich keine vollständige Online-App.

## Ziel und Vorbereitung

Repository Credo1121/Organizational-Analysis, Branch main. Remote vor Mutation geprüft: 62f6aa2bb8aaa692b04d8b607d35a9b65ece3b40. Kein Force-Push. Nur bewusst ausgewählte Quell-/Dokumentationsdateien, keine node_modules, .next, Datenbanken, lokalen .env-Dateien oder Browser-Traces. Musterprüfung auf gängige Schlüssel/Private Keys ohne Treffer; kein vollständiger Secret-Scan-Nachweis.

Vorausgegangene PoC-Prüfungen: [CHG-002](../qa/CHG-002.md). Neue Pages-Generierung und Struktur werden vor dem Push geprüft. Keine Datenmigration für die GitHub-Übergabe.

## Aktivierung durch Repository-Eigentümer

1. Repository-Sichtbarkeit bei Bedarf selbst in GitHub ändern.
2. Settings → Pages → Build and deployment → Source: Deploy from a branch.
3. Branch main und Verzeichnis /docs wählen, Save.
4. Abschluss des Pages-Deployments abwarten; anschließend die von GitHub angezeigte URL prüfen.

Die lokale npm-Eigenschaft private:true schützt vor versehentlicher npm-Veröffentlichung; sie steuert nicht die GitHub-Sichtbarkeit.

## Betrieb und Rollback

Die statische Demo hat keine Datenbank und keine Migration. Updates: npm run build:pages, erzeugte Demo prüfen und committen/pushen. Rücknahme: den betreffenden Pages-Änderungscommit mit git revert rückgängig machen und regulär pushen, oder Pages in den Repository-Einstellungen deaktivieren. Kein Löschen/Zurücksetzen von Kundendaten erforderlich. Verantwortlich für Repository-Sichtbarkeit und Pages-Aktivierung: Repository-Eigentümer. Kein Hosting mit echten Kundendaten durch diese Übergabe freigegeben.

Lokale Prüfungen vor Push: npm run build:pages PASS, Typecheck PASS, Formatprüfung des neuen Skripts PASS, sechs Fach-/SQLite-Testgruppen PASS. docs/index.html über einen isolierten lokalen HTTP-Server in Chromium geöffnet; Desktop 1440×1000 und Mobile 390×844 geprüft, Priorisierung und Dateidownload PASS.
