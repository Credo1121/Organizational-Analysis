# ADR-001: Lokaler modularer Monolith

Status: Für PoC gewählt, 06.11.2026. Nutzer hat den Featureentwurf mit Pseudonymisierungs-Ergänzung bestätigt und die Implementierung beauftragt. Keine produktive Freigabe.

Next.js mit TypeScript und React; ein lokaler Prozess mit expliziten Frontend-, Domain- und Servermodulen. Separate Backend-Services erzeugen für einen lokalen Bearbeiter keinen Nutzen. SQLite über Node 24 `node:sqlite`, kein zusätzlicher Datenbankserver. API und Frontend im selben Origin. Zod ist Quelle der Laufzeitverträge. Keine externen Fonts, Telemetrie oder KI-Aufrufe. Gateway bleibt ausdrücklich nicht angebunden.

PoC-Entscheidungen: CSV-Vorlagen plus Spaltenzuordnung; manuelle Begriffe/Namen und strukturierte Personenfelder zur Pseudonymisierung, ergänzende E-Mail-/Telefon-Erkennung, manuelle Freigabe. Originale und Klartext-Zuordnung verbleiben nur im Browser-Arbeitsspeicher bis Importabschluss/Abbruch. Serverseitig werden lediglich HMAC-Fingerprints für konsistente Zuordnung gespeichert; kein Klartext-Verzeichnis. Grenzen: kein Vollständigkeitsversprechen der Erkennung. STAR-Ratings bleiben standardmäßig leer; bei manueller Eingabe muss eine eigene Skalenbegründung hinterlegt werden, keine Übertragung der Prozessskala.

Lokales Einzelkonto mit scrypt-Hash, Cookie-Sitzungen, Loopback-Bindung; kein Passwort im Repo. Vor erster Nutzung Passwort im Terminal setzen. SQLite-Projektstände in Transaktionen, optimistische Versionsprüfung, private Verzeichnis-/Dateirechte. Daten außerhalb des Checkouts. Keine Dateiverschlüsselung durch das App-Login. Ein aktives Projekt; Backup/Wiederherstellung über validierten Projektsnapshot.

Ausbau-/Neubewertungstrigger: mehrere Bearbeiter, andere Zielruntime, interner Betrieb, produktive Kundendaten, Gateway-Freigabe. Umfangreiche Mandanten-, Berechtigungs-, Deployment- oder Verschlüsselungsarchitektur ist nicht Teil dieses PoC.
